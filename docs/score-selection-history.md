작성일: 2026-10-24. 사용자와 합의한 우선순위 **1~3단계**를 구현한다. 기준은 main `d9f432b7593a3ab8eb4bb5cbc425eea8e215146d`이며, 브랜치는 `feat/score-selection-history`다.

2026-10-25 추가: Studio 입력과 좌우 길이 드래그에 관한 아래 당시 설명은 [MuseScore식 입력 변경](musescore-note-entry.md)으로 대체되었습니다. 선택·그룹·음원 분리 히스토리 규칙은 유지합니다.

## 구현 범위

| 입력 / 기능 | 이번 동작 |
| --- | --- |
| 음표 머리 클릭 | 화음의 구성음 하나 선택 |
| 마디 빈 공간 클릭 | 해당 오선의 마디와 모든 성부 선택. 음표 입력 모드에서는 기존 입력 동작 유지 |
| Shift+클릭 | 고정 시작점과 클릭한 곳 사이의 시간·성부·오선 범위 선택. 양 끝의 같은 시점 화음도 모두 포함 |
| 같은 마디·같은 시작 시점에서 Shift+클릭 | 다른 구성음이나 성부를 눌러도 해당 범위의 화음 전체 선택 |
| Ctrl/Cmd+클릭 | 다른 악기·성부에 걸쳐 개별 음표 머리만 추가·해제. 쉼표와 마디는 추가하지 않음 |
| Shift+←/→ | 시작점은 유지하면서 선택 범위 확장·축소. 쉼표와 마디 경계 포함 |
| ↑/↓ | 단일·그룹 모두 반음 이동. 그룹은 선택된 구성음만 동일한 반음 수로 이동 |
| 단일 음표 상하 드래그 | 기존 오선·조표 기준 온음계 이동 유지 |
| 그룹 상하 드래그 | 잡은 음의 이동량을 기준으로 전체 음정을 보존하며 이동 |
| 단일 음표·쉼표 좌우 드래그 | 기존 길이 늘리기·줄이기 유지. 다른 음표를 덮거나 마디를 넘는 편집은 거부 |
| 그룹 길이 변경 | 늘리기·줄이기 모두 불가. 속성 선택기와 좌우 드래그 양쪽에서 차단 |
| Ctrl/Cmd+Z, Ctrl+Y, Ctrl/Cmd+Shift+Z | 악보 Undo/Redo. 제목·구조·조표·박자·음표·기보 템포 변경 포함 |

범위는 시작 시점을 정확한 분수로 비교하고, 두 끝점 사이 성부·오선·악기 행을 모두 포함한다. 같은 박자 번호라도 마디가 다르면 다른 위치다. 음높이 일괄 변경은 화음 구성음 충돌이나 지원 음역(C2~C7) 초과 시 전체를 거부한다. 쉼표와 무율 타악기는 이조하지 않는다.

악보는 악기별 독립 화면 대신 같은 마디와 시작 시점을 정렬한 기본 총보로 표시한다. 각 시스템 시작에 음자리표·조표를, 악보 첫 마디에 박자표를 표시한다. 화면 너비·배율 변경 후에도 음악 ID에 기반한 선택을 유지한다. 선택된 마디는 연보라 배경, 음표 머리는 보라색으로 표시한다. 드래그 선택 상자와 UI의 기본 텍스트 드래그를 차단하며, 입력 칸의 텍스트 편집은 유지한다. 하단 고정 입력 패널은 추가하지 않는다.

드래그 미리보기는 시작 스냅샷에서 계산하고, 완료 시 한 번의 Undo로 기록한다. Escape, pointercancel, capture 상실, 포커스 상실, 화면 재배치 시 전체 악보·선택을 복원한다. 손가락 편집 중 두 번째 손가락이 들어오면 진행 중 편집을 취소한다.

마스터 볼륨, 악기별 프리셋·볼륨·팬·뮤트·솔로는 악보 히스토리에서 제외한다. 음원 설정만 변경해도 Redo는 유지하며, 삭제한 악기를 Undo로 복원할 때도 그 악기의 마지막 믹서 값을 사용한다. JSON 저장에는 기존처럼 이 설정을 포함한다.

## 구조

- `src/project/selection.ts`: SVG와 독립적인 음악 ID, 화음 구성음, 시간·성부 범위, 일괄 이조.
- `src/project/state.ts`: 검증된 편집의 원자적 기록, 선택 복원, 음원 설정과 악보 히스토리 분리.
- `src/notation/renderEnsemble.ts`: 성부·오선의 공통 VexFlow 박자 배치와 렌더러 내부 좌표. 변경된 마디를 교체하며 선택 갱신에는 SVG를 다시 만들지 않는다.
- `src/alpha/EnsembleView.tsx`: Pointer Events, 키보드, 제스처 취소와 음악 명령 연결.

기존 정규 음악 모델·분수 계산·JSON/MusicXML 포맷은 유지한다. `/legacy/` 편집기의 기존 온음계/Shift 반음 키보드 규칙도 유지한다.

## 제한과 후속 작업

- **4단계:** 선택한 내용의 Ctrl/Cmd+C/V. 상대 시간·성부를 보존해 대상부터 아래 성부로 붙여넣고, 부족한 뒷마디만 추가한다. 기존 마디 범위는 덮어쓰고, 부족한 아래 성부의 내용은 무시한다. 한 번의 Undo로 취소한다. **이번에는 구현하지 않았다.** 현재 메뉴의 단일 마디 복사는 기존 기능이다.
- **5단계:** 선택 내용에 맞는 우클릭 도구 메뉴.
- **6단계:** MuseScore 기반 UI·음색·기능과 Songsterr 참고 웹 조작의 추가 개선.
- 기본 총보는 전문 출판용 자동 레이아웃이 아니다. 페이지 모드는 시스템당 1~2마디이며, 긴밀한 기보 배치·연결선·고급 기호·고밀도 대규모 총보 성능은 후속 과제다. 정확히 겹친 동음의 개별 선택에는 입력 성부 선택기를 사용할 수 있다.
- 악보 히스토리는 기존과 같이 최대 100단계다. 실제 Galaxy Tab/S Pen, 사람이 듣는 음색 평가, MuseScore GUI/WASM 실행은 이번에 검증하지 않았다.
- 기존 VexFlow 공유 청크의 500 kB 초과 경고는 남아 있다(약 728.6 kB, gzip 약 390.7 kB). 경고 한도를 높이거나 실패를 숨기지 않았다.

## 검토 방법

1. 브랜치를 받아 Node 고정 버전에서 `npm ci`, `npm run dev`로 실행한다.
2. 같은 화음의 다른 음에 Shift+클릭하고 다른 악기의 음까지 확장한다. Ctrl/Cmd+클릭으로 일부 구성음만 선택해 본다.
3. ↑/↓로 반음 이동, 그룹 좌우 드래그의 거부, 상하 드래그와 Escape/Undo를 확인한다.
4. 믹서를 변경한 뒤 악보를 Undo/Redo해 믹서가 유지되는지 확인한다. 세로 화면과 배율 변경도 확인한다.
5. [비교 화면](https://github.com/ju87-super/PocketScore/compare/main...feat/score-selection-history)에서 사용자가 PR을 생성한다. main 병합·Pages 배포·저장소 공개 범위 변경은 이 작업에 포함하지 않는다.
