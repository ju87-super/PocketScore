# PocketScore 2.0 — MuseScore식 기본 입력

사용자 지시 2026-10-25에 따라 기존 Studio 입력 방식을 변경했다. 기준 main은 PR #6이 병합된 `47e58201deb04dc2d688fca93edbebda9c363586`이며 브랜치는 `feat/musescore-note-entry`다. 선택·그룹·히스토리의 기존 합의는 유지한다.

## 바로 확인하기

파일 → 새 악보에서 악보를 누른 뒤 **N → 5 → C → Shift+E → Shift+G**를 입력한다. 첫 박자에 4분 도미솔 화음이 생기고 다음 입력 위치는 2박에 남아야 한다. **4 → D → 0**을 이어 누르면 8분 레와 8분쉼표가 입력된다.

입력 모드를 켠 채 같은 박자의 다른 높이를 마우스·펜으로 누르면 화음 구성음을 직접 추가한다. 속성 패널에서 3도씩 추가하는 기존 보조 기능도 유지하지만 이제 그 기능에 의존할 필요가 없다. Esc로 입력을 종료하면 Shift/Ctrl 선택 규칙을 사용한다.

| 입력 | 동작 |
| --- | --- |
| N / Esc | 음표 입력 켜기·끄기 / 입력 종료·진행 중 포인터 취소 |
| 3, 4, 5, 6, 7 | 16분, 8분, 4분, 2분, 온음표 |
| . | 지원하는 점음표 토글 |
| A–G | 현재 위치에 음표 입력 후 선택 길이만큼 이동 |
| Shift+A–G | 마지막 입력 음표 또는 단일 선택 화음에 위쪽 구성음 추가. 시간·길이 유지 |
| 0 | 선택 길이의 쉼표 입력 후 이동 |
| ♯ / ♭ / ♮ 도구 | 입력 모드에서는 다음 음의 임시표를 선택. 선택 모드에서는 기존 단일 음 편집 |
| Ctrl/Cmd+Alt+1–4 | 입력 성부 변경·필요한 성부 생성 |
| Delete / Backspace | 선택 구성음 삭제. 전부 삭제하면 같은 길이 쉼표로 대체 |
| Space | 재생 / 일시정지 |
| Ctrl/Cmd+Z, Ctrl+Y, Ctrl/Cmd+Shift+Z | 악보 Undo/Redo |

숫자키·도구는 입력 모드에서 다음 입력 길이를 선택하고, 선택 모드에서는 선택한 단일 이벤트의 길이를 바꾼다. 그룹은 늘리기와 줄이기 모두 거부한다. Studio의 좌우 드래그는 길이를 바꾸지 않는다. 선택 모드의 상하 음높이 드래그, 방향키 반음 이동, 마우스·펜 공통 Pointer Events는 유지한다. `/legacy/`의 기존 입력 프로필과 테스트도 유지한다.

MuseScore v4.7.5의 [실제 단축키 정의](https://github.com/musescore/MuseScore/blob/v4.7.5/src/app/configs/data/shortcuts.xml)에서 N, 음이름, Shift 화음, 길이 숫자, 점, 쉼표, 성부 키를 확인했다. 전체 MuseScore 기능이나 C++/Qt 엔진을 구현했다는 뜻은 아니다.

## 음악 데이터와 안전한 편집

- `src/project/noteEntry.ts`는 SVG와 무관한 분수 시점·성부·화음 입력을 계산한다. 커서·입력 길이·옥타브 기준·대기 임시표는 프로젝트 JSON에 넣지 않는다.
- 명시적인 새 음표 입력은 해당 성부의 대상 시간 범위를 대체한다. 다른 성부와 범위 밖의 시작·길이·음높이를 유지한다. 기존 이벤트의 길이 변경은 계속 뒤 쉼표만 소비할 수 있다.
- 모든 마디·성부 박자 합계와 프로젝트 ID/음역/화음 불변식을 검증한 뒤 한 번에 기록한다. 지원하지 않는 붙임줄 조각이나 마디선 초과는 이유를 알리고 전체 거부한다.
- 마지막 마디 뒤로 입력하면 모든 오선에 뒷마디를 추가한다. 해당 입력과 마디 추가는 Undo 한 번으로 복원한다.
- 화음 추가는 입력 커서를 앞으로 보내지 않으며, 마우스로 화음을 쌓은 뒤 키보드로 다음 음을 입력해도 그 화음을 덮어쓰지 않는다.
- 임시표는 조표와 마디 안의 음이름·옥타브별 상태를 따르고 다음 마디에서 초기화한다. 화음 중복 음과 C2–C7 범위 초과는 거부한다.
- Undo/Redo는 입력 위치도 복원하며 현재 선택한 입력 모드·길이와 믹서·마스터 설정은 유지한다. 입력 설정만 바꿔도 Redo를 지우지 않는다.
- 입력 모드의 탭은 손을 뗄 때만 반영한다. 이동·Esc·pointercancel·포커스 상실·재배치·두 번째 손가락은 진행 중 입력을 취소한다. 입력 칸·IME·컨트롤의 키보드 동작은 보호한다.

## 검증과 제한

단위 테스트는 기존 209개와 신규 입력 14개, 총 223개다. Chromium UI는 기존 47개와 신규 실제 입력 10개, 총 57개이며 기존 SoundFont 통합 4개를 유지한다. 새 UI 검증은 JSON fixture에 화음을 미리 넣는 방식이 아니라 빈 악보에서 키보드·마우스·펜으로 직접 입력한다. 타입 검사, 린트, 프로덕션 빌드와 CI 계약 28개도 실행한다.

Studio 입력 변경으로 의도적으로 바뀐 기존 테스트는 좌우 펜 이동 뒤 길이가 유지되는지, 숫자키로 길이를 변경하고 Undo하는지 검사하도록 바꿨다. 기존 legacy 좌우 길이 드래그, 선택, MusicXML, 오디오, 반음, 조표·박자, 취소 검증은 삭제하거나 생략하지 않는다. [브랜치 Validate 실행 목록](https://github.com/ju87-super/PocketScore/actions/workflows/ci.yml?query=branch%3Afeat%2Fmusescore-note-entry)에서 실제 Actions 결과와 artifact를 확인할 수 있다.

아직 지원하지 않는 입력은 32분·64분·겹온음표, 점16분 등 나머지 점음표, 자동 붙임줄·연음표, MIDI, 리듬 전용/음높이 교체 모드다. 이 기본 입력을 MuseScore 전체와 동일하다고 표현하지 않는다. 음역 C2–C7, 화음 8음, 128마디 등 기존 제한도 유지한다. 기존 약 728.6 kB VexFlow 공유 청크 경고는 남아 있으며 한도를 올려 숨기지 않는다.

실제 Galaxy Tab/S Pen, 사람의 음색 평가, MuseScore GUI/WASM 실행은 검증하지 않았다. 일반 Chromium과 CDP pen/touch 에뮬레이션은 이를 대체하지 않는다.

다중 성부 Ctrl/Cmd+C/V와 우클릭 도구는 앞서 정한 후속 단계로 남는다. 복사된 성부를 대상 아래로 배치하고, 뒷마디를 확장하되 부족한 성부는 무시하며 기존 범위를 덮어쓰는 합의를 변경하지 않는다. main 병합·Pages 배포·공개 범위 변경은 이 작업에 포함하지 않는다. PR은 사용자가 생성한다.
