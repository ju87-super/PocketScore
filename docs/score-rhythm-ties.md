# 3단계 — 32·64분 리듬과 기본 붙임줄

후속 [자동 붙임줄 입력](automatic-tie-input.md)은 아래 최초 구현의 자동 분할 제한을 해제한다.

2026-10-28, main `fab34fbdc3056577c3bec382a8b85352680d70fa`, AGENTS.md와 PR 상태를 확인하고 `feat/rhythm-ties`에서 작업한다. PR #12의 컨테이너 CI 개선을 포함한 최신 main을 기준으로 한다. PR 생성은 사용자가 수행한다.

## 편집

- 상단 음표 도구·속성 길이 선택·우클릭 메뉴에서 32·64분음표/쉼표를 편집한다. 기존 숫자 입력 규칙에 1=64분, 2=32분을 더하며 키보드는 선택 사항이다. 점음표는 점32분·점16분부터 점2분까지 지원한다.
- 같은 성부에 같은 음높이의 음표를 인접하게 입력하고 앞 음을 선택한 뒤 **다음 음과 붙임줄**을 누른다. 화음은 선택한 구성음만 연결한다. 같은 버튼으로 다음 연결을 토글하며, **선택 붙임줄 해제**는 선택한 구성음의 앞뒤 연결을 함께 해제한다. 우클릭·속성에도 같은 명령을 제공한다.
- 마디선과 악보 시스템 경계를 넘는 연결을 지원한다. 쉼표·다른 음높이·다른 성부·악보 끝으로 연결하는 작업은 이유를 알리고 거부한다. 타악기 연결은 비활성화한다.
- 연결된 한 논리 음은 어느 구간에서 음높이·임시표를 바꾸어도 함께 바뀐다. 그룹에 연결 양끝이 모두 포함돼도 한 번만 이동한다. 화음 충돌·음역 초과는 전체 작업을 거부한다.
- 그룹의 길이 변경은 늘리기·줄이기 모두 계속 금지한다. 단일 붙임줄 음표도 먼저 연결을 해제해야 길이를 바꿀 수 있다. 마디를 넘는 연결이 있으면 박자표 변경도 해제 후 수행한다.
- 기존 마디·성부·음표를 삭제하거나 시간 구간을 덮어쓰면 실제로 사라진 끝점의 연결을 끊는다. 같은 위치에 같은 음높이가 다시 생겨도 옛 연결을 자동으로 다시 붙이지 않는다. 덮어쓰기 범위 밖에 남은 음표 조각의 앞/뒤 연결과 실제 재생 시간은 보존한다. 여러 조각이 필요한 자동 분할은 거부한다.
- 복사는 선택된 양끝이 모두 포함된 내부 연결만 보존한다. 일부 화음 구성음·마디 경계·여러 성부와 새 ID를 지원하며, 붙여넣기의 기존 덮어쓰기·아래 성부 배치·마디 추가·Undo 규칙을 유지한다.
- 모든 악보 변경은 Undo/Redo 대상이며 현재 믹서·마스터·음색과 일시 클립보드를 되돌리지 않는다. 상단 스크롤 도구와 문맥 메뉴를 사용하며 고정 하단 입력 패널을 추가하지 않는다.

MuseScore v4.7.5의 [NotationInteraction::addTieToSelection](https://github.com/musescore/MuseScore/blob/3654226c2e99289916916953a98e585a3d3b315a/src/notation/internal/notationinteraction.cpp#L5477)이 선택 연결을 `cmdToggleTie`로 수행하고, 별도의 `addTiedNoteToChord`가 `cmdAddTie(true)`를 호출하는 구조를 확인했다. 이번 단계는 기존 음표의 선택 연결을 구현한다. Qt/C++ 코드를 실행하거나 MuseScore GUI를 검증한 것은 아니다.

## 음악 모델과 조판

`RhythmEvent`의 음표에 선택적 `tieTo: number[]`로 다음 음에 연결하는 MIDI 음높이를 저장한다. 연결 대상은 같은 성부의 바로 다음 이벤트에서 찾고, 빈 시간 없이 실제 음높이가 일치하는지 검증한다. ID·SVG 좌표·렌더러 객체를 연결 데이터로 저장하지 않는다. 기존 v2 JSON 파일은 계속 읽으며 새 필드는 엄격히 검증한다. 이전 앱 버전은 이 필드를 지원하지 않을 수 있다.

길이와 시작은 계속 기약분수다. 최소 격자는 1/64이며 12/8 한 성부의 64분음표 96개를 저장·재로드할 수 있도록 파일 검증 한도를 맞췄다. 전체 16,000이벤트·128마디·음역 C2–C7·서로 다른 화음 8개 제한은 유지한다.

VexFlow는 32·64분 기호·쉼표·4단 빔과 연결 곡선을 모델에서 파생한다. 시스템 사이 연결은 양쪽에 부분 곡선을 그린다. 단일 성부는 줄기 반대쪽, 다중 성부는 성부 방향에 맞춰 곡선을 배치한다. 폭·배율·오선 높이가 바뀌면 다시 배치하며, 기존 마디 캐시도 도착 음의 연결/임시표 변경을 감지한다. MuseScore의 모든 충돌 회피·수동 곡선 조절을 구현한 것은 아니다.

같은 표기의 연결 도착 음은 임시표를 다시 찍지 않는다. 도착 음 자체는 새 마디의 독립적인 임시표 상태를 만들지 않으므로 이후 새 발음에는 필요한 기호를 표시한다. 이명동음으로 표기가 달라지면 필요한 임시표를 유지한다.

## 재생과 파일

- 붙임줄은 성부·화음 구성음별로 하나의 `PlayedNote`와 MIDI Note On/Off로 합친다. 구간별 악보 하이라이트는 그대로 유지한다. 템포가 마디 경계에서 바뀌면 실제 구간별 초를 더하고, MIDI tick은 정확한 분수에서 계산한다.
- SpessaSynth의 위치 이동은 이전 Note On을 건너뛴다. 그래서 긴 지속음 중간으로 이동하면 소리가 사라지는 문제를 실제 PCM 테스트에서 확인했다. 이제 해당 시점에 이미 발음 중이어야 할 선율 키만 한 번 복원한다. 정확히 시작하는 음은 MIDI에 맡기고 겹친 동음은 중복 발음하지 않으며 드럼을 다시 치지 않는다.
- 일시정지 중 위치 이동은 지정한 UI 위치를 유지하고 재개 시 실행한다. 재생을 시작한 뒤 시점을 설정해 시퀀서가 긴 음의 다음 이벤트로 건너뛰는 문제도 피한다. Note Off는 기존 MIDI 일정이 처리하며 pause/stop은 잔류 음을 제거한다. 복원 시 음색의 발음/엔벌로프는 다시 시작하며 원래 샘플 위상까지 재현한다고 주장하지 않는다.
- MusicXML은 divisions=16으로 64분 격자를 정수로 보존한다. `32nd`·`64th`, 단일 점, 구성음별 `<tie>`와 `<notations><tied>` 시작/끝을 입출력한다. 한 표현만 있는 파일도 읽으며 둘 다 있으면 일치해야 한다. 시작/끝 누락·다른 음높이/성부·중복·쉼표 연결은 전체 파일을 거부한다.
- 고정 `rhythm-ties.musicxml`은 2성부·화음 일부·마디선·32/64분·점32분쉼표의 독립적인 기준이다. 기존 `tied.musicxml`은 끝이 없는 잘못된 연결로 계속 거부한다. 고정 파일과 실제 내보낸 XML 모두 공식 MusicXML 4.0 XSD 검증을 통과했다.

## 검증

새 단위 41개(음악 22·재생 7·XML 12)를 추가해 전체 303개다. 새 Chromium 13개는 입력/펜 에뮬레이션·구성음·반음/히스토리·시스템 분할·임시표 캐시·클립보드·거부/포커스·XML/JSON·밀집 빔·390/800 화면·C2/C7 곡선 배치를 검사한다. 기존 ID 일부가 같은 파일을 다시 열어도 새 연결 정보를 그대로 보존하는 재로드 회귀 검사도 포함한다. 긴 오르간 지속음을 실제 MS Basic SF3로 재생하고 위치 이동·pause/resume·stop 후 무음을 검사하는 통합 시나리오도 추가했다.

기존 검사는 삭제하거나 생략하지 않는다. 길이 목록이 늘면서 옵션 번호가 바뀐 기존 브라우저 테스트 2곳은 실제 표시 이름인 **2분**을 고르도록 수정해 원래의 음표 덮어쓰기 금지·박자 축소 거부 검증을 유지한다.

로컬 타입·ESLint·actionlint·35 CI/WASM 도구 계약·프로덕션 빌드·잠금 파일 검증과 단위 **303/303**을 통과했다. Chromium은 기존/신규 **111개 전체**와 이후 추가한 **JSON 재로드 1개**가 성공했다. 전체 실행 179.9초와 추가 실행 3.2초이며 브라우저 실패·생략·재시도는 0개다. 실제 SF3/PCM **5/5**는 빌드 포함 39.1초에 성공했다. 최종 커밋은 GitHub에서 Chromium **112개 전체**를 다시 검증한다.

## 제한과 다음 범위

자동으로 마디선을 넘는 새 음표를 분할하거나 여러 조각으로 재표기하는 입력은 아직 거부한다. 점64분·점온음표, 겹점, 연음표, 다른 성부/오선으로 연결, 타악기·laissez-vibrer·repeat jump용 붙임줄과 수동 곡선 조절은 후속이다. 지원하지 않는 MusicXML 요소·속성은 계속 진단하며 조용히 버리지 않는다.

실제 Galaxy Tab/S Pen·MuseScore GUI·실제 Pages 배포·WASM 엔진 검증은 수행하지 않는다. 기기 에뮬레이션은 실물 검증을 대체하지 않는다. main 병합·Pages 배포·저장소 공개 범위와 보호 설정을 변경하지 않는다.
