# 1단계 — 빔·간격·줄바꿈 개선

2026-10-27 사용자가 승인한 첫 목표를 Studio 기본 화면에 적용한다. 최신 main `5bbdaabe3089caae55121a69f4c571c87c85b0f3`과 AGENTS.md를 확인하고 `feat/basic-engraving`에서 작업했다. 열린 WASM PR #2와 MuseSampler 연구 PR #8은 변경하지 않았다. PR 생성은 사용자가 수행한다.

## 기준과 구현

MuseScore Studio v4.7.5의 다음 소스를 내려받아 읽고, 기존 VexFlow 5의 Beam/Formatter API로 별도 구현했다.

- [groups.cpp](https://github.com/musescore/MuseScore/blob/v4.7.5/src/engraving/dom/groups.cpp): 박자·음표 길이에 따른 기본 빔 구분, 4/4의 세부 박 분할, 자동 빔에서 쉼표 제외.
- [systemlayout.cpp](https://github.com/musescore/MuseScore/blob/v4.7.5/src/engraving/rendering/score/systemlayout.cpp): 시스템 머리의 음자리표·조표 확보, 마디별 간격 누적, 가용 폭을 넘는 마디를 다음 시스템으로 이동.

upstream의 C++/QML·앱 자산을 복사하거나 MuseScore 엔진을 실행한 것은 아니다. 소스는 GPL-3.0-only이며 이번 코드는 기존 React/TypeScript/VexFlow 편집기의 독립 구현이다.

### 자동 빔

| 박자 | 기본 묶음 |
| --- | --- |
| 2/4, 3/4 | 4분음표 박 단위 |
| 4/4 | 8분음표는 반 마디 단위. 인접 박에 16분음표가 있으면 4분음표 박에서 분리 |
| 3/8, 6/8, 9/8, 12/8 | 점4분음표, 즉 8분음표 세 개 단위 |

쉼표·빔 대상이 아닌 길이·시점의 빈틈에서 묶음을 끊는다. 성부·오선·마디를 넘겨 묶지 않으며 혼자 남는 음표에는 기존 꼬리를 표시한다. 화음은 하나의 리듬 이벤트로 묶는다. 점8분+16분의 정확한 분수 시점도 처리한다.

성부가 하나면 묶음의 음높이를 기준으로 기둥 방향을 정하고, 여러 성부면 1·3성부는 위, 2·4성부는 아래로 유지한다. 기존 `autoStem`이 명시한 성부 방향을 덮어쓰던 부분도 수정했다. 빔의 세로 높이 차이는 오선 한 칸 이내로 제한해 넓은 마디와 큰 도약에서 선이 악보 위로 잘리지 않게 한다.

### 음표·쉼표·화음 간격

모든 마디를 가장 복잡한 마디의 폭에 맞추던 방식에서, 각 마디의 실제 음표·화음·임시표·점·성부를 VexFlow Formatter로 측정하는 방식으로 바꿨다. 같은 시점은 모든 악기/오선의 공통 리듬 격자에 놓고, 마디별 최소 폭에 읽기 위한 여유를 더한다. 따라서 복잡한 화음과 많은 임시표에는 더 많은 공간을 배정한다.

한 성부를 단독으로 채우는 하나의 쉼표 이벤트는 온마디쉼표 모양으로 가운데에 놓는다. VexFlow의 표시 길이와 실제 분수 길이를 분리하므로 2/4·3/4·3/8 같은 박자에서도 음악 데이터는 바뀌지 않는다. 여러 이벤트로 저장된 쉼표를 합쳐 음악 데이터를 변경하지 않는다.

### 줄바꿈과 화면 위치

실제 최소 폭을 순서대로 누적해 시스템을 구성한다. 한 줄에 고정 1~2마디를 넣던 제한을 없앴고, 빈 공간은 각 마디의 리듬 본문 폭에 따라 배분한다. 아주 짧은 마지막 시스템은 과도하게 늘리지 않는다. 시작 마디마다 음자리표·조표를 다시 확보하고 박자표는 전체 악보 시작에만 둔다.

좁은 화면에서 한 마디가 가용 폭보다 넓으면 그 마디를 압축하지 않고 가로 이동할 수 있게 한다. 다음 시스템의 줄바꿈은 계속 실제 화면 폭으로 계산하므로 복잡한 한 마디가 나머지 줄까지 넓히지 않는다. 연속 보기는 한 시스템을 유지한다.

패널·확대·화면 폭 변경 시 같은 마디의 상대 세로 위치를 유지한다. 재배치로 앞 마디가 같은 줄에 들어와도 기준 마디를 바꾸지 않도록 스크롤 앵커를 보완했다. 음악 모델과 JSON/MusicXML, 재생 시점, 단축키, 그룹 선택/길이 금지, Undo/Redo 규칙은 유지한다. 조판 결과를 음악 모델이나 히스토리에 저장하지 않는다.

## 검증

새 단위 테스트 `src/notation/engraving.test.ts` 17개는 7박자·혼합 길이·쉼표·시점 빈틈·화음·좁은 화면·밀도별 폭·연속 보기와 모델 불변을 검증한다. CI의 Music Engine Tests에 `src/notation`을 포함시켜 새 테스트도 필수 검사에서 실행한다.

새 실제 Chromium 검사 `tests/e2e/engraving.spec.ts` 11개는 다음을 검증한다.

- 7개 박자의 실제 SVG 빔 경로, 쉼표에서 분리, 16분음표와 점8분+16분 묶음.
- 각 박자에서 조표 0·-7·+7의 기호와 음표가 SVG 및 해당 마디의 가로 범위 안에 들어오는지 확인.
- 복잡한 화음의 더 넓은 마디 폭, 두 마디를 넘는 배치, 390/800/1280px 재배치, 시스템 머리 기호와 단일 박자표.
- 여러 성부/오선의 동일 박자 정렬, 기둥 방향, 빔이 있는 화음의 실제 편집·Undo와 그룹 길이 차단.
- C2/C7 도약과 150% 확대에서 빔·글리프·44px 클릭 영역의 범위 확인.
- 편집·재배치 후 증분 SVG의 빔 경로/클릭 좌표가 같은 악보를 새로 열었을 때와 일치.
- 조판 전후 저장한 악보의 분수 시점·음높이·길이·ID 보존.

기존 검사는 삭제하지 않았다. Alpha의 고정 2마디/줄 기대는 전체 마디/오선 보존과 실제 시스템별 머리 기호 검사로 갱신했다. 더 많은 마디가 한 줄에 들어가므로 스크롤 회귀 fixture는 64마디로 늘리고, 같은 줄의 첫 마디 대신 기준 마디 자체의 상대 위치를 검증한다.

## 제한과 다음 작업

이번 단계는 기본 자동 빔·수평 간격·반응형 시스템 배치다. 수동 빔 분리/연결, 오선을 넘는 빔, 붙임줄·연음표, 인쇄 페이지 조판과 모든 기호의 충돌 해소는 후속 범위다. MusicXML의 수동 `<beam>` 등 미지원 요소는 기존처럼 명시적으로 거부한다. 특정 박자 경계를 넘는 싱코페이션의 모든 MuseScore 빔 규칙까지 동일하다고 주장하지 않는다. Legacy 편집기의 기존 표시·조작은 유지한다.

실제 Galaxy Tab/S Pen과 MuseScore GUI 비교는 수행하지 않았다. Chromium 캡처·pen/touch 에뮬레이션을 실기기 검증으로 보고하지 않는다. 기존 약 728.6kB 공유 청크 경고를 숨기지 않았다. main 병합·Pages 배포·공개 범위와 저장소 설정 변경은 실행하지 않는다.
